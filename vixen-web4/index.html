Networking Fundamentals for New Operators

A reference document. Not exciting. Read it anyway.

This document exists because too many people skip the basics and go straight to tools they don't understand. Tools are not a substitute for understanding what is actually happening on the wire. Read this first. The tools will make more sense afterward.

1.What a Packet Actually Is

Every piece of data sent across a network is broken into packets before it moves anywhere. A packet is not the whole message. It is a fragment of it, wrapped in headers that describe where it came from, where it is going, and how it should be reassembled once it arrives.

A single web page load can involve dozens or hundreds of packets. Most people never see a single one of them. That is by design. It is also exactly why looking at them directly tells you things a browser will never show you on its own.

2.HTTP, In Plain Terms

HTTP is a request and response protocol. A client asks for something. A server answers. Every request has a method, most commonly GET to retrieve something or POST to send something. Every response has a status code, a set of headers, and usually a body.

None of this is encrypted by default. HTTPS adds encryption on top of HTTP. HTTP by itself hides nothing from anyone capturing the traffic in transit.

3.DNS, Briefly

Domain names exist for people. Computers use numbers. DNS is the system that converts one into the other. When a browser is told to load a domain, the first thing that happens, before any actual page content is requested, is a DNS lookup to find the numeric address behind that name.

DNS lookups are a common place for things to be misconfigured, cached longer than expected, or in some cases used to move data somewhere it should not be moving. Understanding what a normal DNS lookup looks like makes an abnormal one much easier to notice.

4.TCP and the Handshake

Before two machines exchange any actual data over TCP, they perform a three-step handshake: SYN, SYN-ACK, ACK. This confirms both sides are ready and agrees on initial sequencing before a single byte of real content moves.

This happens for nearly every connection you will ever look at. It is easy to skip past when reading a capture. It is also one of the fastest ways to confirm whether a connection actually completed or was dropped partway through.

5.What a Browser Doesn't Show You

A rendered web page is the end result of a large number of requests, most of which happen without any visible indication to a normal visitor. Stylesheets, scripts, fonts, images, and increasingly, background data requests initiated by the page's own code after it finishes loading.

Viewing a page's source shows you what was written. It does not show you what the page does once it starts running.

Most browsers include a developer toolkit for exactly this reason. It is typically opened with F12, or by right-clicking anywhere on a page and selecting Inspect. Among its tabs is one specifically for observing every network request a page makes, including the ones that happen quietly, after the page has already loaded.

6.Closing Note

None of this is advanced. All of it is necessary. Operators who skip this step tend to miss things that were never actually hidden, only unwatched.
